티켓 $ARGUMENTS 를 현재 세션에 클레임한다.

**주의: Git 작업은 하지 않는다.**

1. `.work/BOARD.md`를 읽는다
2. 해당 티켓의 상태를 확인한다:
   - `[ ]`이 아니면 클레임 불가 → 사유 출력
   - 도구 컬럼이 `Cursor`이면 클레임 불가 → "이 티켓은 Cursor에서 작업합니다" 출력
   - 의존성 티켓이 `[x]`가 아니면 클레임 불가 → 사유 출력
   - 파일 범위가 다른 진행중 티켓과 겹치면 경고
3. 클레임 처리:
   - BOARD.md에서 티켓 상태를 `[~S{N}]`로 변경
   - 담당 컬럼에 `S{N}` 기입
   - 활성 세션 테이블 업데이트
4. 해당 티켓의 파일 범위에 있는 기존 코드를 읽고 이해한다
5. **Plan 모드로 진입하여 구현 계획을 제시한다**

출력:
```
✅ T{XXX} 클레임 완료
유형: {feat/fix/refactor/test/docs/chore}
파일 범위: {파일 목록}
의존성: {해결됨/없음}

📖 기존 코드 분석:
- {관련 파일 요약}

📋 구현 계획:
1. {단계 1}
2. {단계 2}
3. {단계 3}

이 계획으로 진행할까요?
```
