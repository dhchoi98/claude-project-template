# 자가 검증 루프 (Self-Verification Loop)

## 핵심 원칙

> **검증 없이 "완료했습니다"라고 말하지 않는다.**
> 사용자에게 깨진 코드를 넘기는 것은 가장 큰 신뢰 손상이다.

CLAUDE.md "절대규칙 4"의 운영 매뉴얼.

## 검증 순서

다음을 순서대로 실행한다. 도구가 없으면 그 단계는 건너뛴다 (절대 조작/거짓말 금지).

### 1. 타입 체크 (정적)

| 언어 | 명령 |
|------|------|
| Python | `mypy <변경된 파일>` 또는 `pyright` |
| TypeScript | `tsc --noEmit` |
| Go | `go vet ./...` |
| Rust | `cargo check` |

### 2. 린트

| 언어 | 명령 |
|------|------|
| Python | `ruff check <변경된 파일>` |
| TypeScript/JS | `eslint <변경된 파일>` |
| Go | `gofmt -l <변경된 파일>` |
| Rust | `cargo clippy --quiet` |

### 3. 테스트

- **변경한 파일에 대응하는 테스트만** 먼저 실행 (빠르게)
- 통과하면 해당 모듈 전체 테스트
- 모듈도 통과하면 끝 (전체 스위트는 사용자 요청 시에만)

```bash
# 예: Python — 좁게 → 넓게
pytest tests/core/test_engine.py -x          # 1단계: 한 파일
pytest tests/core/ -x                         # 2단계: 모듈
# pytest 전체는 사용자 요청 시
```

### 4. 빌드 (해당하는 경우)

- TypeScript: `tsc` 또는 `next build`
- Rust: `cargo build`
- Go: `go build ./...`

## 실패 시 행동

1. **에러 메시지를 끝까지 읽는다** (스택 트레이스 포함)
2. 가장 위에 나오는 실패 한 건만 먼저 본다 (cascade 무시)
3. 원인 추정 → 수정 → **다시 1단계부터** 검증
4. 같은 에러가 3회 반복되면 가정이 틀린 것. 다른 접근으로 전환
5. 5회 이상 시도해도 안 풀리면 **사용자에게 보고** (혼자 헤매며 토큰 낭비 금지)

## 보고 형식

검증 결과를 사용자에게 보고할 때:

```
변경 사항:
  - <파일1>: <한 줄 설명>
  - <파일2>: <한 줄 설명>

검증 결과:
  - 타입 체크: ✅ / ❌ / 해당 없음
  - 린트:      ✅ / ❌ / 해당 없음
  - 테스트:    ✅ <N>개 통과 / ❌ / 해당 없음
  - 빌드:      ✅ / ❌ / 해당 없음
```

## 안티 패턴

- "테스트 작성했습니다" (실행 안 함) — **금지**
- "타입 에러는 무시해도 됩니다" — **금지** (사용자가 판단)
- "이 정도면 동작할 것 같습니다" — **금지**
- 실패한 테스트를 `skip` 처리하거나 삭제 — **절대 금지**
- `# type: ignore` 무차별 살포 — **금지** (사유 주석 필수)
