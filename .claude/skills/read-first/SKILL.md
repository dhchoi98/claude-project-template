# Read-First 절차

## 핵심 원칙

> **추측으로 코드를 쓰지 않는다.** 모르면 읽고 안다.
> 토큰 비용보다 잘못 쓴 코드를 되돌리는 비용이 훨씬 크다.

CLAUDE.md "절대규칙 1"의 운영 매뉴얼.

## 읽기 순서 (위에서 아래로)

### 1. 진입점 문서
- `CLAUDE.md` (루트) — 절대규칙, 모드, 엄격도
- `PLAN.md` — 현재 어떤 Phase에 있는지
- 작업 대상 디렉토리의 `CLAUDE.md` (있으면) — 해당 모듈의 로컬 규칙
- `.work/MISTAKES.md` — 과거 실수 (중복 회피)

### 2. 작업 대상 파일
- 수정할 파일 **전체** 읽기 (부분 읽기 금지 — 컨텍스트 누락)
- 파일 상단 docstring에서 의도/책임 파악

### 3. 의존 관계
- **이 파일이 임포트하는 모듈** — 어떤 인터페이스에 의존하는가
- **이 파일을 임포트하는 모듈** — 변경이 누구에게 영향 주는가 (Grep으로 호출처 검색)
- 인터페이스(ABC/Protocol)가 있으면 정의 + 모든 구현체 위치 파악

### 4. 테스트
- 대응하는 테스트 파일 (`tests/...`) — 명세서이자 사용 예시
- 테스트가 없는 모듈을 만진다면, 그 사실 자체가 위험 신호

### 5. 관련 ADR (있으면)
- `.work/decisions/` 에서 이 모듈에 대한 아키텍처 결정 검색

## 언제 멈출 것인가

다음 질문에 모두 답할 수 있으면 읽기 충분:

1. **이 파일/함수의 책임이 무엇인가?** (한 줄로 요약 가능?)
2. **변경이 누구에게 영향을 주는가?** (호출처 목록)
3. **테스트가 어떤 계약을 보장하는가?** (없으면 추가 필요한가?)
4. **비슷한 변경이 과거에 있었는가?** (`git log`/`MISTAKES.md`)

답할 수 없는 게 있으면 더 읽는다.

## 안티 패턴

- 파일 일부만 읽고 수정 — **금지** (사라진 컨텍스트가 버그의 원천)
- 호출처 확인 없이 시그니처 변경 — **금지**
- 기존 테스트를 안 보고 새 로직 추가 — **금지** (기존 계약 위반 가능성)
- "비슷한 코드 본 적 있으니까 그대로" — **금지** (이 프로젝트의 컨벤션 우선)

## 도구 가이드

| 목적 | 도구 |
|------|------|
| 전체 파일 읽기 | `Read` |
| 특정 함수 호출처 | `Grep` (pattern: `함수명\(`) |
| 디렉토리 구조 | `Glob` (pattern: `**/*.py`) |
| 광범위 탐색 | `Agent` (subagent_type=Explore) |
| 단순 키워드 검색 | `Grep` 단독 |

광범위한 탐색은 Explore 서브에이전트에 위임하는 것이 메인 컨텍스트를 보호한다.
