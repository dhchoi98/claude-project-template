## 티켓 큐

> 상태: `[ ]` 대기 → `[~S{N}]` 진행중 → `[x]` 완료 → `[!]` 블로커
> 도구: `CC` = Claude Code (설계/아키텍처/고난이도) | `Auto` = Cursor Auto (무제한 구현) | `Premium` = Cursor Premium (복잡한 에러/디버깅, 크레딧 차감) | `MAX` = Cursor MAX (대공사, 추가 과금) | `BG` = --teleport 백그라운드 (장시간/비동기) | `Any` = 무관

## 티켓 설계 규칙

### 유형
- `feat` — 새 기능 개발
- `fix` — 버그 수정
- `refactor` — 리팩토링
- `test` — 테스트 작성
- `docs` — 문서화
- `chore` — 설정/빌드/인프라

### 도구 배정 기준

| 도구 | 역할 | 모델/모드 | 과금 | 적합한 작업 |
|------|------|----------|------|------------|
| `CC` | 수석 아키텍트 | Claude Code (터미널) | API 종량제 | 아키텍처 설계, 디자인 패턴, 멀티파일 구조 변경, 스켈레톤/인터페이스 생성 |
| `Auto` | 시공반장 | Cursor Auto 모드 | **무제한** (Pro $20) | 구현체 채우기, 비즈니스 로직, API, UI, 보일러플레이트, 반복 작업 |
| `Premium` | 트러블슈터 | Cursor Premium (Claude/GPT-4.5) | 기본 크레딧 차감 | 복잡한 에러 분석, 멀티파일 참조 테스트, 고난이도 디버깅 |
| `MAX` | 대공사 | Cursor MAX Mode | **추가 과금** | 전면 리팩토링, 대규모 마이그레이션 (사용 후 즉시 끌 것) |
| `BG` | 백그라운드 워커 | CC --teleport | API 종량제 | 코드베이스 분석, 대량 문서화, 커버리지 분석, 보안 스캔 |
| `Any` | — | — | — | 어느 도구든 상관없는 작업 |

**일반적인 흐름:**
```
CC (설계) → Auto (무제한 구현) → Premium (막힐 때만 잠깐)

  T001 CC     "인증 아키텍처 설계"     → T002 Auto    "로그인 API 구현"     → T003 Auto    "인증 테스트 스위트"
  T004 CC     "DB 스키마 & 모델 설계"  → T005 Auto    "CRUD 구현체 작성"   → T006 Auto    "모델 테스트 & 문서"

💡 비용 최적화: Auto를 기본으로 → 막히면 잠깐 Premium → 해결되면 다시 Auto
```

### 좋은 티켓의 조건
1. **독립적**: 다른 티켓과 파일 범위가 겹치지 않는다
2. **명확한 범위**: 파일 범위 컬럼에 구체적인 파일/디렉토리가 명시된다
3. **검증 가능**: 완료 기준이 명확하다 (테스트 통과, 빌드 성공 등)
4. **적절한 크기**: 한 세션에서 완료할 수 있는 크기

### 충돌 방지를 위한 티켓 쪼개기 예시
```
❌ 나쁜 예: T001 "사용자 기능 전체 구현" (범위 너무 넓음)

✅ 좋은 예 (CC→Auto 파이프라인):
  T001 CC     "User 모델 & 인증 아키텍처 설계"   파일: src/models/user.*, docs/auth.md
  T002 Auto   "회원가입 API 구현"                파일: src/api/auth.*
  T003 Auto   "회원가입 UI 폼"                   파일: src/pages/signup.*
  T004 Auto   "회원가입 테스트"                   파일: tests/auth/*
  T005 Auto   "인증 API 문서"                    파일: docs/api/auth.*
  T006 CC     "인증 미들웨어 & 보안 검토"          파일: src/middleware/auth.*
```

### 보드 조작
1. **클레임**: `[ ]` → `[~S{N}]` + 담당에 세션 번호
2. **완료**: `[~S{N}]` → `[x]` + 완료 이력에 추가
3. **블로커**: `[!]` + 사유 기록
4. **의존성**: 선행 티켓이 `[x]`가 아니면 클레임 불가
